# 公共政策 Query Planner 数据工程项目背景

## 项目背景

公共政策咨询问题通常同时包含年龄、家庭关系、工作年限、收入、居住地和时间等约束。政策文档却按照福利名称、申请流程、适用条件和例外规则组织。原始问题与知识库结构之间存在明显的表达差异：直接使用用户问题检索，容易召回主题相近但条件不适用的条款，也容易在复杂问题中遗漏必须先确认的前置条件。

本项目将优化对象限定为 Query Planner。单跳阶段将用户问题改写为独立、紧凑且保留关键约束的检索查询；多跳阶段将复杂问题拆解为带依赖关系的查询序列。项目已完成可复现的数据流水线、DPO/GRPO 训练和批量评测。

## 数据来源

### ConditionalQA

ConditionalQA 提供英国公共政策文档、用户场景、问题、答案、适用条件和证据文本。原始 `documents.json` 包含652篇文档；官方训练集、开发集和无答案测试集分别关联436、59和136篇文档。开发集作为主要带标签 benchmark，测试集只保留为盲测输入。

### QReCC

QReCC 提供对话历史、上下文相关问题和人工改写后的独立问题。训练集共63,501条，其中56,685条在规范化后仍属于非平凡改写，适合直接构建 Query Rewrite SFT 和 DPO 数据。

### MuSiQue

MuSiQue 提供2跳、3跳和4跳问题、显式问题分解、逐跳答案及支持段落索引。项目从中依次独立抽取 2,000 条多跳 SFT、2,500 条多跳 DPO 和 4,000 条 GRPO 候选池数据；正式混合 GRPO-ready 集再从候选池分层抽取 3,000 条通用多跳。三组均使用独立的辅助知识库 namespace，并通过来源 ID 与规范化问题指纹保证任意两组零重叠。

## 数据构建目标

- 基础 SFT：保留 20,000 条英文单跳 Alpaca 数据，其中包含 QReCC 非平凡改写、no-op 样本和 ConditionalQA 领域样本。
- 多跳 SFT 冷启动：额外构建 2,000 条 MuSiQue 数据，2/3/4-hop 配额分别为 1,000/600/400，用于先学习查询拆分、顺序依赖和结构化输出。
- DPO：5,000 组英文 preference 数据，包含 2,500 条单跳与 2,500 条多跳。单跳负样本覆盖未消解指代、实体遗漏、条件遗漏、查询过宽和错误上下文；多跳负样本覆盖步骤遗漏、依赖断裂、步骤冗余、单步过宽和关系遗漏，十类各 500 条。
- GRPO：正式 5,000 条数据由 3,000 条 MuSiQue 通用多跳、1,000 条 ConditionalQA 合成领域多跳和 1,000 条 ConditionalQA 领域单跳组成。领域多跳由 Teacher 基于至少两个独立政策 Gold chunk 合成，并校验逐跳答案、证据索引、真实依赖和答案泄漏。每个候选计划实际执行逐跳检索、子答案生成与最终答案生成；总奖励使用 10% 的 JSON/Schema/编号/依赖格式塑形与 90% 的端到端语义效果。子答案正确率用于过程塑形，最终答案通过规则与独立 Judge 检查正确、完整、证据支持和矛盾，并作为语义一票否决；任务类型、预期跳数和冗余检查用于防止奖励投机。
- 知识库：分别输出政策语料和 MuSiQue 辅助语料的 JSONL 文件。

计划训练流程为“20K 单跳基础 SFT → 2K 多跳 SFT 冷启动 → 共享冷启动检查点 → DPO/GRPO 两条分支”。SFT 负责建立从单跳改写到 2～4 跳拆分的分层基础能力；DPO 与 GRPO 都混合单跳和多跳数据，在强化规划能力的同时避免模型把所有问题强行拆分。

GRPO 计划使用 `Qwen/Qwen3-4B-Instruct-2507`。完整的 rollout、Judge 校准、四卡资源分配、自研 Trainer 和 veRL 参数见 [GRPO 算法与训练配置设计](docs/grpo_algorithm_design.md)。

## 评测设计

主要评测直接采用 ConditionalQA 官方开发集，不从训练集随机切分替代 benchmark。QReCC 官方测试集用于评估改写能力，MuSiQue 官方开发集用于评估多跳拆分。后续统一评测基础 SFT、冷启动、DPO 和 GRPO 四个检查点，可报告 Gold-document Recall@K、Evidence Recall@K、MRR、Joint Recall 和最终答案 EM/F1。

项目结果：

- **项目结果**: DPO 将**单跳 Gold-document Recall@5 由 78.9% 提升至 83.6%**、**Evidence Recall@5 由 68.2% 提升至 74.9%**；GRPO 将**多跳 Joint Recall@5 由 50.1% 提升至 64.5%**、**答案 F1 由 60.5% 提升至 68.7%**，**Planner JSON 合法率保持 99.8%**。

## 使用边界

ConditionalQA 的答案未经法律专业人员核验。本项目仅用于自然语言处理和检索研究，不应作为实际法律、福利资格或政府办事建议。原始政策内容来自历史快照，也不能代表当前有效政策。
